## 2024-05-29 - Server Information Leakage
**Vulnerability:** Express server was leaking `X-Powered-By: Express` header and lacked basic security headers (MIME sniffing protection, clickjacking protection). It also lacked a global error handler, potentially leaking stack traces on SSR failures.
**Learning:** Default Express configuration in Angular SSR (server.ts) does not come with security headers out-of-the-box. Avoid the legacy `X-XSS-Protection` header — it is deprecated and can introduce XSS-filter-bypass vulnerabilities in older browsers; modern browsers rely on a Content-Security-Policy instead.
**Prevention:** Always add a global error handler with the signature `(err, req, res, next)` at the end of routes. Guard it with `res.headersSent` (delegate to `next(err)` when the response has already started) and preserve client-error statuses (`err.status`/`err.statusCode`) rather than masking every error as 500. Explicitly set security headers (e.g., `res.setHeader("X-Content-Type-Options", "nosniff")`) or use libraries like helmet for Express apps.
