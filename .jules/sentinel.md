## 2026-05-31 - [Missing Security Headers on Cloudflare Worker Responses]
**Vulnerability:** The Cloudflare Worker (`worker/index.ts`) served responses without clickjacking or MIME-sniffing protections. The HTML document and static assets returned via `env.ASSETS.fetch` carried no `X-Frame-Options`, `Content-Security-Policy`, or `X-Content-Type-Options` headers, leaving the app exposed to clickjacking and content-type sniffing in production.
**Learning:** Per-handler header logic (e.g. only setting headers inside a `jsonResponse` helper) silently skips responses produced elsewhere — most importantly the HTML/static assets from `env.ASSETS.fetch`, which is the path real users hit. Note: the Angular SSR/Express `server.ts` was removed (#113) and is never executed in production, so the Worker is the only request path that needs hardening.
**Prevention:** In Cloudflare Workers, wrap **every** outgoing response in a single helper that sets the security headers (`X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Content-Security-Policy: frame-ancestors 'none'`). Pair `X-Frame-Options` with the CSP `frame-ancestors` directive, which is the modern clickjacking defence honoured by current browsers (X-Frame-Options remains only as a legacy fallback).
